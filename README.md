# Лабораторная работа 1 — численное интегрирование

Виткулевский Т. В., Волков К. В., АВТ-412.
Метод правых прямоугольников, `f(x)=(1+x²)/(x³√(2+x))`, `[2;5]`.

## Сборка и запуск в Windows

Открыть `L1pp.slnx` в Visual Studio, выбрать **Release / x64**, собрать и запустить.
Пути к заголовкам, import library и копирование DLL уже настроены в проекте.
Либо выполнить в PowerShell из корня проекта:

```powershell
./build.ps1
./x64/Release/L1pp.exe
```

Ввести три целых числа отдельными строками: число разбиений, число потоков
основного вычисления, максимум потоков для тестирования. Рекомендуемый пример:
`20000000`, `8`, `16`. По умолчанию используется пять повторов.

Воспроизведение приложенного эксперимента (7 повторов):

```powershell
./run-experiments.ps1
# Или напрямую:
./x64/Release/L1pp.exe 20000000 8 16 7 results
./x64/Release/L1pp.exe --self-test
```

N: от 1 до 10^12, число потоков: от 1 до min(N,256), повторы: нечётное число
от 1 до 99. Большие N могут потребовать длительного ожидания. Некорректный
ввод отклоняется с сообщением и ненулевым кодом завершения.

Для Linux: `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`,
`cmake --build build`, `ctest --test-dir build`, `./build/L1pp`.
На Linux используется системная POSIX Threads; этот путь не проверялся на данной Windows-машине.

## Методика

Время — медиана повторов `steady_clock`, включая создание и ожидание потоков,
локальные вычисления и редукцию, без консольного и файлового вывода. Прогрев
каждой конфигурации выполняется до измерений. Порядок технологий и числа
потоков перемешивается между повторами (seed 412). Ускорение в сводной таблице
считается от одного рабочего потока той же технологии. В основной таблице
отдельно приведено сравнение с прямым последовательным циклом без создания
потока; основания сравнения явно различаются.

POSIX возвращает выделенный в куче `double*` из worker и получает его через
`pthread_join`; память освобождается в вызывающем потоке. `std::thread`
получает все параметры по отдельности, результат — через `std::ref`.
Границы блоков учитывают остаток деления; все N узлов обрабатываются ровно один раз.
Суммирование Кэхэна уменьшает ошибки округления. На современных MSVC определение
`HAVE_STRUCT_TIMESPEC` предотвращает конфликт старого pthread.h с UCRT.

Гарантированная оценка ошибки квадратуры: `|I-I_N| <= 1.16015625/N`.
Для абсолютной точности eps достаточно `N >= ceil(1.16015625/eps)`.
Эталон: `0.45096855032232666016863367519517954957789301445977`.
Граница относится к квадратуре в точной арифметике; при предельно малых eps
необходимо отдельно учитывать округление floating point.
